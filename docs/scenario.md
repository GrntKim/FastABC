# 사용 시나리오

FastABC가 실제로 어떻게 쓰이는지 한 사람의 하루로 보여 줍니다. 시연 영상, 결과보고서의 사용 시나리오, 포스터의 흐름도가 모두 이 문서를 따릅니다.

## 등장인물과 상황

- **김 조교**: 컴퓨터공학과 대학원생, 「정보보호개론」(2026-2학기, 01분반) 조교
- **할 일**: 중간고사 서술형 3문항, 40명분 채점
- **지금 방식의 문제**: 40장을 같은 기준으로 끝까지 읽어야 하고, 뒤로 갈수록 판단이 흐려진다. 담당 교수는 AI가 점수를 매기는 것은 원하지 않는다. 점수에 대한 책임은 채점자에게 있어야 한다.
- **가진 것**: 교수가 준 채점 기준, LMS에서 내려받은 답안 CSV(학번, 이름, 1번·2번·3번)

## 흐름

| 단계 | 화면 | 채점자가 하는 일 | 시스템이 하는 일 |
|---|---|---|---|
| 0. 로그인 | `/login` | 이메일과 비밀번호로 로그인한다 | 로그인하지 않고 다른 주소를 열면 로그인 화면으로 보낸다. 채점자는 자기 과목만 본다 |
| 1. 과목과 시험 | 과목 목록 `/` → 과목 `/courses/{id}` | 학과, 연도와 학기, 과목명, 분반을 넣어 「정보보호개론 01분반」을 추가한다. 과목 화면에서 시험 「중간고사」를 추가한다 | 과목을 학기와 함께 보여 주고, 분반은 두 자리(`01`)로 맞춘다. 같은 과목을 두 번 만들면 알려 준다 |
| 2. 문항 만들기 | 시험 `/exams/{id}` → 새 문항 | "문항 추가하기"로 들어가 번호, 제목, 문제를 넣고, 채점 기준을 항목마다 적는다: 항목 이름, 가점·감점, 배점, AI가 확인할 내용("답안이 공격 예시를 구체적으로 든다") | 번호는 다음 번호로 미리 채운다. 주제를 벗어난 답안을 거르는 항목을 자동으로 넣고, 채점자가 쓴 "답안"을 판단기가 읽는 표기로 바꾼다. 빈 항목이나 잘못된 배점은 다시 그린 화면에 알린다 |
| 3. 답안 올리기 | 시험 화면 "답안 올리기" | LMS의 CSV를 한 번 올린다 | 학번 열과 문항 번호 열(`1번`, `문항 2`, `3`)을 찾아 문항마다 답안을 넣는다. 빈 칸은 미제출, 이미 있는 학생과 성적 확정된 문항은 건너뛰고 그 수를 알린다. 이름·학번·이메일·전화번호를 지운 본문을 따로 만들어 외부 API에는 그것만 보낸다 |
| 4. 채점 시작 | 문항 `/problems/{id}` | 문제와 채점 기준 표를 확인하고 "답안 n개 채점 시작"을 누른다 | 판단 모델이 모든 칸을 1차 판단하고(답안당 약 0.3초), 확신 낮은 칸만 LLM이 백그라운드에서 다시 판단한다. 진행 칸이 2초마다 "AI가 다시 보는 중… n개 항목"과 판단 결과별 개수를 갱신하고, 끝나면 "채점하러 가기"를 보여 준다 |
| 5. 순서대로 읽기 | 채점 `/problems/{id}/review/{답안 id}` | 확인이 필요한 첫 학생부터 연다. 문제 아래 답안을 읽고, 항목별 점수 칸을 본다 | 왼쪽 학생 목록에 학생마다 확인 필요 항목 수(다 끝난 학생은 ✓)를 붙인다. 확인이 필요한 항목에 이유를 붙인다: AI 의견이 갈림(두 판단을 나란히) / AI가 다시 확인함(판단 이유) / 무작위 점검. 점수 칸은 미리 채우지 않고 AI 추천 칸만 점선으로 표시한다 |
| 6. 판단하기 | 같은 화면 | 표시된 항목의 점수 칸을 눌러 확정한다. 다른 칸을 누르면 바로 고쳐지고, 고른 칸을 다시 누르면 취소된다. 다 보면 "확인 필요 외 n개 항목 추천대로 확정하고 다음 학생으로"를 누른다 | 누른 줄만 새로 그린다. 확정은 추천과 비교해 추천 수용 / 수정 / 직접 입력으로 기록한다. 버튼은 AI가 확신한 항목 중 무작위 점검이 아닌 것만 확정하고, 확정할 칸이 남은 다음 학생을 연다. 마지막이면 문항 화면으로 돌아간다 |
| 7. 성적 확정 | 문항 화면 결과 | 학생별 항목 점수와 총점, "직접 확인 n개 · AI 추천을 고친 n개 · 추천대로 n개"를 보고, 책임 확인에 체크한 뒤 확정한다 | 미확정 항목이 남았으면 그 수와 "이어서 채점하기"만 보여 준다. 확정하면 확정자(로그인한 계정)·시각·결과 해시를 새 버전으로 기록하고 문항을 잠근다. 잠긴 문항은 점수를 바꾸거나 답안을 더할 수 없다 |
| 8. 개정 | 같은 화면 "성적 개정" | 이의신청이 들어오면 사유를 적고 개정한 뒤, 점수를 고치고 다시 확정한다 | 이전 버전에 개정 시각과 사유를 남기고 잠금을 푼다. 다시 확정하면 다음 버전(v2)이 되고, 확정 이력에 모든 버전이 남는다 |
| 9. 시험 결과 | 시험 화면 | 학생별 합계를 확인하고, "CSV로 내보내기"로 받아 LMS에 올린다 | 학번으로 문항 점수를 묶어 합계를 낸다. 답안이 없는 문항은 "미제출"(0점), 미확정 항목이 남은 학생은 합계를 비워 둔다 |

## 시연

- **영상:** `seed_demo.py --empty`로 1·2번 문항만 있는 중간고사에서 시작한다. 3번 「대칭키와 공개키 암호」를 직접 만들고(채점 기준은 `data/demo/q3_crypto.json`), 시험 화면에서 `data/demo/midterm_answers.csv`(40명)를 올린다. 문항마다 채점을 시작하고, 순서대로 읽기 → 성적 확정 → 시험 결과로 이어 간다. "문항이 몇십 개여도 같은 방식이고, 시연은 퀴즈 수준 3문항"으로 설명한다.

## 이 시나리오가 보여 주는 것

- **AI는 점수를 확정하지 않는다.** 모든 칸은 채점자가 눌러야 확정되고, 추천 수용·수정·직접 입력으로 기록이 남는다 (5~8단계).
- **모든 답안은 사람이 한 번은 본다.** 문항 전체를 한 번에 확정하는 버튼은 없다. 채점자는 학생 답안을 순서대로 읽고, AI는 판단이 흐려지기 쉬운 항목을 짚어 주며 확신 높은 항목을 한 번에 확정하게 돕는다. AI가 확신하지 못하거나 의견이 갈린 항목은 채점자가 정한다. 사람과 AI가 서로를 보완한다.
- **봐야 할 곳이 표시된다.** 평가셋(2문항, 150칸)에서 판단 모델이 확신을 가지고 자동 처리한 칸이 87%이고, 그중 94.6%가 채점자의 판단과 일치했다. 나머지는 이유와 함께 채점자에게 넘어간다.
- **기다리지 않는다.** 첫 추천은 답안당 약 0.3초에 나온다 (LLM만 쓰면 약 10초). LLM 재판단은 백그라운드에서 돈다.
- **학생 정보는 밖으로 나가지 않는다.** 외부 API에는 식별 정보를 지운 답안만 보낸다 (3단계).

## 하지 않는 것

- AI 생성 답안 판정, 표절·유사도 검사
- LMS 직접 연동, 과목 공유·역할 구분 (계정은 자기 과목만 본다)
- 객관식 채점
- 논술형의 총체적 채점, 계산 문제의 숫자 검산 (채점 기준이 "이 내용을 썼는가"로 나뉘는 서술형에 맞춘 도구다)
- 학생 이의 제기 처리 (개정으로 점수 변경과 사유만 기록한다)
