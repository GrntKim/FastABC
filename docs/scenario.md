# 사용 시나리오

FastABC가 실제로 어떻게 쓰이는지 한 사람의 하루로 보여 줍니다. 시연 영상, 결과보고서의 사용 시나리오, 포스터의 흐름도가 모두 이 문서를 따릅니다.

## 등장인물과 상황

- **김 조교**: 컴퓨터공학과 대학원생, 「정보보호개론」(2026-2학기, 01분반) 조교
- **할 일**: 중간고사 서술형 2번 "SQL 인젝션의 원리와 방어 방법을 설명하시오" 답안 40장 채점
- **지금 방식의 문제**: 40장을 같은 기준으로 끝까지 읽어야 하고, 뒤로 갈수록 판단이 흐려진다. 담당 교수는 AI가 점수를 매기는 것은 원하지 않는다. 점수에 대한 책임은 채점자에게 있어야 한다.
- **가진 것**: 교수가 준 채점 기준(평소 문장), LMS에서 내려받은 답안 CSV(학번, 이름, 답안)

## 흐름

| 단계 | 화면 | 채점자가 하는 일 | 시스템이 하는 일 |
|---|---|---|---|
| 1. 과목 | 과목 목록 `/` | 학기 탭에서 2026-2학기를 고르고, 「정보보호개론 01분반」을 처음 한 번 추가한다 | 과목마다 문항 수와 진행 단계를 보여 준다 |
| 2. 문항 만들기 | 새 문항 | 문제를 붙여 넣고, 채점 기준을 교수가 준 문장 그대로 붙여 넣는다 ("원리 설명 2점, 공격 예시 1점, prepared statement 2점 … 이스케이프만으로 막는다고 하면 1점 감점") | LLM이 기준 문장을 **판단 질문**(항목마다 예/아니오 또는 수준)으로 바꿔 편집기에 채운다 (10~20초, 저장 안 함) |
| 3. 기준 확인 | 같은 화면, 3. 판단 질문 확인 | 질문을 읽고 애매한 것을 고친다 (예: "공격 예시"에 "일반적인 말만 있으면 아니오"를 추가). 배점을 확인하고 저장한다 | 형식 오류는 해당 항목 옆에 표시한다 |
| 4. 답안 올리기 | 문항 → 관리 탭 | LMS에서 받은 CSV를 그대로 올린다 | 이름·학번·이메일·전화번호를 지운 답안만 외부 API로 보낸다. 이름은 저장하지 않고, 학생은 "학생 1, 2, …" 라벨로 보인다 |
| 5. 채점 시작 | 관리 탭 | "채점 시작"을 누른다 | 판단 모델이 모든 칸을 1차 판단한다 (답안당 약 0.3초). 확신 낮은 칸만 LLM이 백그라운드에서 다시 판단한다 |
| 6. 확인 필요한 곳만 보기 | 채점 탭 (학생별) | 상단의 "확인 필요 n칸 · 다음 확인 필요 학생"을 따라간다. 답안을 열면 항목별 근거 문장을 찾아 색으로 표시하므로, 표시된 곳부터 확인한다 | 확인이 필요한 학생부터 정렬한다. 점수 칸은 미리 채우지 않고 추천만 보여 준다 |
| 7. 판단하기 | 같은 화면, 점수표 | 칸마다 **추천 수용 / 수정 / 직접 입력** 중 하나를 고른다. 두 판단이 다른 칸, 추천이 없는 칸은 직접 판단한다 | 칸의 경로를 표시한다: 자동 / LLM 확인 / 직접 판단 / 주제 벗어남 / 샘플 검토 |
| 8. 나머지 일괄 수용 | 같은 화면 | 확인 필요 칸을 다 보면 "나머지 일괄 수용"을 누른다. 잘못 눌렀으면 일괄 취소한다 | 확신 높은 자동 칸만 수용한다. 무작위로 뽑은 샘플 검토 칸(자동 칸의 약 10%)은 빠지므로 직접 본다 |
| 9. 항목별 점검 | 항목별 보기 `/review` | 학생 간 일관성이 걱정되는 항목(예: "설명의 정확성")만 골라 모든 학생의 해당 칸을 나란히 보고, 기준이 흔들린 칸을 고친다 | 항목 하나의 칸들을 모아 보여 준다 |
| 10. 성적 확정 | 결과 **(구현 예정)** | 요약(수용 / 수정 / 직접 입력 칸 수)을 보고, 이름을 적고 책임 확인에 체크한 뒤 확정한다 | 확정자·시각·결과 해시를 기록하고 잠근다. 고치려면 사유를 적고 개정하며, 다시 확정하면 새 버전으로 남는다 |
| 11. 내보내기 | 결과 | 점수 CSV를 내려받아 LMS에 올린다 | 학번, 항목별 점수, 총점을 담는다. 파일 이름에 확정 버전과 해시가 붙는다 **(구현 예정)** |

## 이 시나리오가 보여 주는 것

- **AI는 점수를 확정하지 않는다.** 모든 칸은 채점자가 수용·수정·직접 입력해야 확정되고, 기록이 남는다 (6~10단계).
- **봐야 할 곳만 본다.** 평가셋(2문항, 150칸)에서 판단 모델이 확신을 가지고 자동 처리한 칸이 87%이고, 그 정확도는 94.6%였다. 채점자가 반드시 볼 칸(직접 판단, LLM 확인, 샘플 검토)은 약 다섯 칸 중 한 칸이다.
- **기다리지 않는다.** 첫 추천은 답안당 약 0.3초에 나온다 (LLM만 쓰면 약 10초). LLM 재판단과 근거 찾기는 백그라운드나 답안을 열 때만 실행된다.
- **채점 기준은 채점자 말로.** JSON이나 프롬프트를 몰라도 평소 쓰던 문장으로 기준을 넣고 고칠 수 있다 (2~3단계).
- **학생 정보는 밖으로 나가지 않는다.** 외부 API에는 식별 정보를 지운 답안만 보낸다 (4단계).

## 하지 않는 것

- AI 생성 답안 판정, 표절·유사도 검사
- LMS 직접 연동, 로그인·권한 관리 (로컬 실행 전제)
- PDF·워드 답안 업로드 (CSV만)
- 학생 이의 제기 처리
