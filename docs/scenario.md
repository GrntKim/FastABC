# 사용 시나리오

FastABC가 실제로 어떻게 쓰이는지 한 사람의 하루로 보여 줍니다. 시연 영상, 결과보고서의 사용 시나리오, 포스터의 흐름도가 모두 이 문서를 따릅니다.

## 등장인물과 상황

- **김 조교**: 컴퓨터공학과 대학원생, 「정보보호개론」(2026-2학기, 01분반) 조교
- **할 일**: 중간고사 서술형 2번 "SQL 인젝션의 원리와 방어 방법을 설명하시오" 답안 40장 채점
- **지금 방식의 문제**: 40장을 같은 기준으로 끝까지 읽어야 하고, 뒤로 갈수록 판단이 흐려진다. 담당 교수는 AI가 점수를 매기는 것은 원하지 않는다. 점수에 대한 책임은 채점자에게 있어야 한다.
- **가진 것**: 교수가 준 채점 기준(평소 문장), LMS에서 내려받은 답안 CSV(학번, 이름, 답안)

## 흐름

| 단계 | 화면 | 채점자가 하는 일 | 시스템이 하는 일 |
|---|---|---|---|
| 0. 로그인 | 소개 `/welcome` → 로그인 `/login` | 처음 열면 소개 화면(무엇을 하는지, 예시 화면, 쓰는 순서)에서 "가입하고 시작하기"를 누르고 이름·이메일·비밀번호로 가입한다. 이후에는 로그인한다 | 로그인하지 않고 첫 화면을 열면 소개 화면을, 그 밖의 주소로 들어오면 로그인 화면을 보여 주고, 로그인하면 원래 가려던 화면으로 돌려보낸다. 채점자는 자기 과목만 본다. 과목이 하나도 없으면 환영 화면에서 쓰는 순서(문항 만들기 → 답안 올리고 채점 → 확인할 곳만 보고 확정)를 세 단계로 보여 준다 |
| 1. 과목과 시험 | 과목 목록 `/` → 과목 | 학기 탭에서 2026-2학기를 고르고, 「정보보호개론 01분반」을 처음 한 번 추가한다. 과목 화면에서 "시험 추가"로 「중간고사」를 만든다 | 과목마다 문항 수와 진행 단계(준비 / 채점 중 / 채점 끝 / 성적 확정)를 보여 주고, 확인할 곳이 남은 과목을 표시한다. 과목 안에서는 시험마다 문항을 번호순으로 묶어 진행 막대와 "학생 n / 40명 완료"를 보여 주고, 문항이 없으면 문항 하나를 채점하는 세 단계를 보여 준다 |
| 2. 문항 만들기 | 새 문항 | 중간고사의 "이 시험에 문항 추가"로 들어가 번호(2번)를 확인하고, 문제를 붙여 넣고, 채점 기준을 교수가 준 문장 그대로 붙여 넣은 뒤 "항목으로 나누기"를 누른다 ("원리 설명 2점, 공격 예시 1점, prepared statement 2점 … 이스케이프만으로 막는다고 하면 1점 감점") | LLM이 기준 문장을 **채점 항목**(이름, 가점·감점, 충족 여부·수준별, 배점, AI가 확인할 내용)으로 나눠 편집기에 채운다 (10~20초, 저장 안 함) |
| 3. 기준 확인 | 같은 화면, 3. 채점 항목 확인 | 항목마다 "AI가 확인할 내용"을 읽고 애매한 것을 고친다 (예: "공격 예시"의 미충족으로 볼 경우에 "일반적인 말만 있으면 미충족"을 추가). 배점을 확인하고 저장한다 | 형식 오류는 해당 항목 옆에 표시한다. 문제와 관련 없는 답안을 거르는 확인은 따로 쓰지 않아도 자동으로 들어간다 |
| 4. 답안 올리기 | 문항 → 준비 탭 | LMS에서 받은 CSV를 그대로 올린다 | 이름·학번·이메일·전화번호를 지운 답안만 외부 API로 보낸다. 채점 화면에는 학생 이름과 학번이 보이고, "이름 가리고 채점"을 켜면 `S001`, `S002` 같은 라벨만 보인다(이 브라우저의 모든 채점 화면에 적용) |
| 5. 채점 시작 | 준비 탭 | "채점 시작"을 누른다 | 판단 모델이 모든 칸을 1차 판단하고(답안당 약 0.3초) 바로 채점 탭으로 넘어간다. 확신 낮은 칸만 LLM이 백그라운드에서 다시 판단한다 |
| 6. 확인 필요한 곳만 보기 | 채점 탭 (학생별) | 왼쪽 학생 목록에서 확인 필요 항목 수가 붙은 학생부터 연다. 시험지처럼 문제 아래 답안이 보이고, 항목별 근거 문장이 색으로 표시되므로 표시된 곳부터 확인한다 | 맨 위 진행 막대에 "AI가 확신한 항목 75%"와 확정 / AI가 확신(한 번에 확정 가능) / 확인 필요 비율을 보여 주고, "확인할 학생 31명 · 한 명당 1~3개 항목"처럼 남은 일을 학생 단위로 알린다. "어떻게 고르나요?"를 펼치면 고르는 방식을 설명한다. 확인이 필요한 학생부터 정렬한다. 점수 칸은 미리 채우지 않고 추천만 보여 준다. 확인이 필요 없는 항목은 한 줄로 접어 둔다("확인 필요만 펼치기"·"모두 펼치기"로 바꿀 수 있다). 시험지가 화면 위로 넘어가면 점수 줄이 화면 맨 위에 붙고, 학생 이름(가렸으면 라벨)과 "답안 보기"(답안 전체 펼침)가 나타난다 |
| 7. 판단하기 | 같은 화면, 항목별 점수 | 펼친 항목 안의 "답안에서" 인용(근거 문장과 앞뒤 문맥)을 읽고, 맥락이 더 필요하면 인용을 눌러 시험지의 그 위치로 간다. 항목마다 받을 수 있는 점수가 선택 칸 한 줄로 보이고(AI 추천 칸은 점선 표시만, 미리 채우지 않음), 칸을 누르는 것이 곧 확정이다. 고른 칸이 그 자리에 채워져 남고, 다른 칸을 누르면 바로 고쳐진다. AI 의견이 갈린 항목은 선택 칸 아래 "1차"·"재확인" 표시와 나란히 놓인 두 판단 카드(결과와 이유)를 보고 고른다. 카드를 눌러도 그 판단으로 확정된다. 확인할 항목을 다 보면 화면 아래에 붙어 있는 막대의 "확인 필요 외 n개 항목 추천대로 확정"으로 이 학생의 나머지를 확정하고, 같은 막대의 "다음 확인 필요 학생"으로 넘어간다 | 확인이 필요한 항목에 이유를 붙인다: AI 의견이 갈림 / AI가 확신하지 못함 / 무작위 점검. 이 학생의 점수(지금까지 n / 만점)를 크게 보여 주고, 확정은 추천 수용 / 수정 / 직접 입력으로 기록한다 |
| 8. 나머지 확정 | 같은 화면 | 학생마다 확정하지 않고 한 번에 끝내려면, 확인이 필요한 항목을 다 본 뒤 위쪽 진행 막대 옆의 "남은 항목 추천대로 확정"을 누른다. 잘못 눌렀으면 학생마다 아래 막대의 "모두 취소"로 되돌린다 | 확인이 필요 없는 칸만 추천대로 확정한다. 무작위 점검 칸(확신 높은 칸의 약 10%)은 빠지므로 직접 본다 |
| 9. 항목별 점검 | 항목별 보기 `/review` | 학생 간 일관성이 걱정되는 항목(예: "설명의 정확성")만 골라 모든 학생의 해당 칸을 나란히 보고, 기준이 흔들린 칸을 고친다 | 항목 하나의 답안들을 모아 보여 준다. 맨 위와 항목마다 진행 막대를 두고, 항목 탭에는 확인 필요 답안 수(다 끝난 항목은 ✓)를 붙인다. 기본은 확인이 필요한 답안만 보이고, 미확정·전체로 넓힐 수 있다 |
| 10. 성적 확정 | 결과 탭 | 채점이 덜 끝났으면 진행 막대와 "채점하러 가기"만 보인다. 다 끝나면 "직접 확인한 항목 n개 · AI 추천을 고친 항목 n개"와 막대(AI가 확신해 추천대로 확정 / 직접 확인 / AI 추천을 고침), 학생별 총점을 보고, 책임 확인에 체크한 뒤 확정한다 | 로그인한 계정을 확정자로 하여 시각, 결과 해시와 함께 기록하고 잠근다. 화면에는 버전(v1)과 확정자, 시각이 보이고 해시는 기록에 남는다. 고치려면 사유를 적고 개정하며, 다시 확정하면 새 버전으로 남는다 |
| 11. 내보내기 | 결과 탭 | 점수 CSV를 내려받아 LMS에 올린다 | 학번, 이름, 항목별 점수, 총점을 담는다. 파일 이름에 확정 버전과 해시가 붙는다 |
| 12. 시험 결과 | 시험 결과 `/exams/[id]` | 과목 화면의 "시험 결과"를 연다. LMS에서 채점이 끝난 객관식 점수 CSV(학번, 점수)를 "객관식 점수 가져오기"로 올리고, 시험 전체 CSV를 내려받는다 | 학번으로 문항별 결과와 가져온 점수를 묶어 학생마다 합계를 낸다. 열마다 문항 진행 단계를 붙이고, 답안이 없는 문항은 "미제출"(0점으로 합산), 확정하지 않은 문항이 있는 학생은 합계를 "채점 중"으로 둔다. 모든 문항이 성적 확정이면 그렇게 표시한다 |

## 이 시나리오가 보여 주는 것

- **AI는 점수를 확정하지 않는다.** 모든 칸은 채점자가 수용·수정·직접 입력해야 확정되고, 기록이 남는다 (6~10단계).
- **봐야 할 곳만 본다.** 평가셋(2문항, 150칸)에서 판단 모델이 확신을 가지고 자동 처리한 칸이 87%이고, 그 정확도는 94.6%였다. 채점자가 반드시 볼 칸(AI 의견이 갈린 칸, AI가 확신하지 못한 칸, 무작위 점검 칸)은 약 다섯 칸 중 한 칸이다.
- **기다리지 않는다.** 첫 추천은 답안당 약 0.3초에 나온다 (LLM만 쓰면 약 10초). LLM 재판단과 근거 찾기는 백그라운드나 답안을 열 때만 실행된다.
- **채점 기준은 채점자 말로.** JSON이나 프롬프트를 몰라도 평소 쓰던 문장으로 기준을 넣고 고칠 수 있다 (2~3단계).
- **학생 정보는 밖으로 나가지 않는다.** 외부 API에는 식별 정보를 지운 답안만 보낸다 (4단계).

## 하지 않는 것

- AI 생성 답안 판정, 표절·유사도 검사
- LMS 직접 연동, 과목 공유·역할 구분 (로컬 실행 전제, 계정은 자기 과목만 본다)
- PDF·워드 답안 업로드 (CSV만)
- 객관식 채점 (LMS·OMR이 낸 점수를 가져와 시험 결과에 더하기만 한다)
- 논술형의 총체적 채점, 계산 문제의 숫자 검산 (채점 기준이 "이 내용을 썼는가"로 나뉘는 서술형에 맞춘 도구다)
- 학생 이의 제기 처리
